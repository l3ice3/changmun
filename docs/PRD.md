## 1. 개요

### 1.1 문제 정의
정부 창업 지원금은 많지만 흩어져 있고, 예비·극초기 창업자는 (1) 자신이 자격이 되는지 모르고(특히 사업자등록 전), (2) 공고 용어(사업화자금·업력 등)가 어렵고, (3) 신청 방법을 모른다. 기존 모아보기 서비스는 사업자 보유를 전제해 첫 화면부터 막힌다. 정보 나열이 아니라 **진입장벽 제거**가 필요하다.

### 1.2 제품 한 줄 요약
> 예비·극초기 창업자와 대학생을 위한, 내 단계에 맞는 지원금만 골라주는 **지원금 전담 비서**.

### 1.3 타겟 사용자
- **주 사용자**: 예비 창업자(사업자등록 전) · 극초기 창업자(업력 3년 미만) · 창업에 관심 있는 대학생
- **부 사용자**: 바이브코더(개발자 예비창업자) — 별도 페르소나 아님, "예비/초기 + 기술·R&D 카테고리" 조합으로 커버

## 2. 목표와 비목표

### 2.1 Goals (MVP, 측정 가능)
1. 3개 공공 소스(K-Startup 전량 / 기업마당 `searchLclasId=06` / 온통청년 `mclsfNm=창업`)를 **일 1회 배치로 수집**하는 파이프라인 가동. 재실행 멱등(UPSERT), 필수필드 누락 레코드는 스킵+로그.
2. **페르소나 4탭(예비/대학생/초기/전체)이 쿼리로 정확 작동.** K-Startup 공고의 `target_*` 채움률 ≥ 95%(구조화 필드 기반이라 가능).
3. **dedup 오합치 0** (출시 전 표본 50쌍 수동 검수 기준). 중복 공고는 canonical 1건만 리스트 노출.
4. **event_log를 서비스 오픈 1일차부터 적재** — 아하 선행지표(공고 상세 진입→원문 클릭률, 찜율)를 측정 가능한 상태로.
5. 공고 상세 페이지가 **검색엔진에 색인**됨(SSG/ISR, 메타태그 완비).

### 2.2 Non-Goals ⚠️
1. **로그인(OAuth) 지원 — In-Scope로 확장**(팀 3인 합의). 단 **익명 사용도 계속 기본** — 로그인은 서버측 찜 동기화 등 선택 기능이며 로그인 없이도 전 기능을 쓸 수 있다. 개인화·추천은 여전히 Phase 3.
2. **AI 추천 없음** — MVP는 규칙 기반 필터만.
3. **민간 공고 수집 없음** — 크롤링·수작업 등록은 Phase 2.
4. **공공기관 추가 소스 탐색 없음** — 표본 검증으로 3대 API가 공공 영역을 닫음을 확인(기획서 §6). R&D(SMTECH·과기부)·중소벤처24는 Phase 2.
5. **알림(이메일/푸시) 없음.**
6. **세무·법인전환 콘텐츠 없음** — "지원금 전담" 범위 유지.
7. 중소기업 종합 포털화 금지 — 타깃은 예비~초기 창업.

### 3.1 In-Scope

- [ ] dedup + 페르소나 부여 배치 (FR-002)

- [ ] SEO: 상세 페이지 SSG/ISR + sitemap
- [ ] 로그인(OAuth: Google·GitHub·Kakao·Naver) + 서버측 찜 동기화 — 익명 사용 유지(스코프 확장, 팀 3인 합의)

### 3.2 Out-of-Scope ⚠️
- 추천 피드, 단계 전환 안내(비서 기능 전부)
- 관리자 웹 UI(수동 작업은 스크립트로 대체)
- 민간 공고 등록 화면
- 알림, 커뮤니티/후기, 통계 대시보드
- 다국어

> ※ **다크(나이트) 모드는 지원**한다(Phase 1에서 Out-of-Scope → In-Scope로 변경, 스코프 확장 승인). 좌측 사이드바 토글 + `html.dark` 색 토큰. 구현 규칙: `.claude/rules/web.md` §8.
>
> ※ **로그인(OAuth: Google·GitHub·Kakao·Naver)은 지원**한다(Out-of-Scope → In-Scope, 팀 3인 합의). 익명 사용이 계속 기본이고 로그인은 **서버측 찜 동기화** 등 선택 기능. 스키마 `app_user`(data-model §8), **PII 최소 수집**(이메일·provider 식별만) + 개인정보처리방침 필요.
>
> ※ **마이페이지(프로필 이미지)는 지원**한다(2026-07-08, Out-of-Scope → In-Scope, 팀 3인 합의). 로그인 사용자의 프로필 이미지 업로드(1MB 이하)·기본 이미지 되돌리기·계정 정보 표시·로그아웃. 스키마·API는 data-model §8 / api-spec §5. 그 외 계정 설정(닉네임·탈퇴 UI 등)은 여전히 후속.

## 4. 기능 요구사항

### FR-001: 공고 수집 파이프라인 (Python)

| 항목 | 내용 |
|---|---|
| 우선순위 | Must |
| 연결 AC | AC-001 ~ AC-005 (`AC.md`) · 매핑 상세는 `data-model.md` §6/6-B/6-C |

**유저 스토리**
> 운영자로서, 매일 최신 공고가 자동 반영되도록, 3개 API를 수집·정규화해 DB에 적재한다.

**상세 동작**
1. 입력: K-Startup(JSON, 전량) / 기업마당(RSS·XML, `searchLclasId=06`) / 온통청년(JSON, `mclsfNm=창업`)
2. 처리: 소스별 매핑(`data-model.md` §6, 6-B, 6-C) → 표준 enum 정규화(§7) → `(source, external_id)` UPSERT
3. 출력: `opportunity` 갱신 + 수집 리포트 로그(신규/갱신/스킵/미지값 건수)

**엣지 케이스 ⚠️**

| 상황 | 기대 동작 |
|---|---|
| 필수필드(`external_id`/`title`) 누락 | 해당 레코드 스킵 + 로그 (파이프라인 중단 금지) |
| 기업마당 JSON 깨짐 | 애초에 RSS(XML)로 수집 (data-model 6-B 규칙) |
| 미지의 category/enum 값 | `기타`로 적재 + 원본값 로그 (열린 enum) |
| 날짜 형식 이탈("~" 누락, 빈값) | 해당 필드 NULL + raw 보존, 상시(`is_always_open`) 판정 규칙 적용 |
| API 응답 실패/타임아웃 | 소스 단위 재시도 N회 → 실패 시 해당 소스만 건너뜀(다른 소스는 진행) + 실패 로그 |
| 재실행(같은 날 2회) | UPSERT로 멱등 — 중복 행 생성 금지 |
| 공고가 API에서 사라짐 | 삭제하지 않음(이력 보존), `updated_at`만 갱신 안 됨 (data-model §2 — 매 UPSERT 갱신 컬럼) |

### FR-002: dedup & 페르소나 부여 배치

| 항목 | 내용 |
|---|---|
| 우선순위 | Must |
| 연결 AC | AC-006 ~ AC-010 (`AC.md`) · 설계는 `data-model.md` §6-D |

**유저 스토리**
> 사용자로서, 같은 공고가 출처만 다르게 2~3번 보이지 않고, 기업마당 공고도 내 페르소나 탭에 잡히길 원한다.

**상세 동작**
1. 수집 직후 1패스: 정규화 키 생성 → 마감일 블로킹 → 스코어링(0.6 제목 + 0.25 기관 + 0.15 기간, 임계 0.85) → Union-Find 그룹핑 → `dedup_group_id` 부여
2. canonical 선정: K-Startup 우선 → `is_canonical` 설정
3. 페르소나 3단계: 구조화(K-Startup 직접) → 상속(그룹 공유) → 텍스트 키워드 규칙(기업마당 잔여분)

**엣지 케이스 ⚠️**

| 상황 | 기대 동작 |
|---|---|
| 유사하지만 다른 공고(차수만 다름 등) | 보수적 임계(0.85)로 미병합 — **오합치 > 놓침** 원칙 |
| 오합치 발견 | 그룹 해제 가능해야 함(비파괴 — 원본 레코드 불변) |
| 페르소나 신호 없음 | `target_*` NULL 유지 → 화면 "조건 미상" (억지 채움 금지) |
| canonical 공고만 마감, 그룹 내 타 출처는 진행 중 | 재배치: 진행 중 레코드를 canonical로 승격 (배치마다 재평가) |
| 그룹에 K-Startup 없음(기업마당끼리) | 정보량 많은 쪽 canonical |

|---|---|
| 우선순위 | Must |

**유저 스토리**
> 예비창업자로서, 가입 없이 탭 한 번으로 내가 자격이 되는 공고만 보고 싶다.

**상세 동작**
1. 지원 대상 선택 4종: 예비(`PRE_STARTUP`) / 대학생(`UNIV_STUDENT`) / 초기(`LT_1Y~LT_3Y`) / 전체 — UI는 필터 드롭다운(탭 → 드롭다운, 2026-07-04 QA. 무가입·선택 한 번은 동일)
2. 보조 필터: 지역 · 카테고리(11종+기타) · 진행상태. 정렬: 마감임박순(기본)/최신순
3. 카드: title·organization·category·region·D-day·"사업자 불필요" 배지·출처. `WHERE is_canonical` + status는 조회 시 계산

**엣지 케이스 ⚠️**

| 상황 | 기대 동작 |
|---|---|
| 결과 0건 | 빈 상태 화면: "조건에 맞는 공고가 없어요" + "전체 공고 보기"(필터 초기화) 유도 |
| `target_*` NULL 공고 | persona 필터에서 제외, 지원 대상 미지정(전체) 조회에서만 노출 + "조건 미상" 표기 |
| 마감 지난 공고 | 기본 제외(진행상태 필터 "전체" 선택 시에만 노출) |
| deadline NULL(상시) | "상시모집" 배지, 마감임박순에서 맨 뒤(NULLS LAST) |
| 페이지 범위 초과 | 빈 배열 + 정상 응답(에러 아님) |

### FR-007: 행동 로그 (event_log)

| 항목 | 내용 |
|---|---|
| 우선순위 | Must |
| 연결 AC | AC-025 ~ AC-027 (`AC.md`) · 스키마는 `db/migrations/V2` (event_log) |

**유저 스토리**
> 팀으로서, 아하 모먼트 선행지표(상세 진입·원문 클릭·찜)를 1일차부터 측정하고 싶다. (소급 불가 — 늦으면 영영 없음)

**상세 동작**
1. 이벤트: `list_view`(탭/필터 포함), `detail_view`, `outbound_click`(원문/신청), `bookmark_add/remove`, `search`
2. 익명 클라이언트 ID(쿠키/로컬 UUID) + 타임스탬프 + 페이로드(JSONB) → append-only 적재

**엣지 케이스 ⚠️**

| 상황 | 기대 동작 |
|---|---|
| 로깅 API 실패 | **UX를 절대 막지 않음** — fire-and-forget, 재시도 없음 허용 |
| 봇/크롤러 트래픽 | UA 기반 최소 필터(완벽 불요, 분석 시 보정) |
| 개인정보 | 비로그인은 익명(이메일·이름 없음). 로그인 사용자만 **최소 PII**(이메일·provider 식별) — 개인정보처리방침. event_log는 항상 익명 |

## 5. 비기능 요구사항

## 6. 기술 제약 ⚠️

| 항목 | 내용 |
|---|---|
| 레포 구조 | **모노레포 1개**: `apps/web`(Next.js) + `apps/api`(Spring) + `apps/ingest`(Python) + `/docs`(계약 문서) + `/db/migrations`(Flyway). 기존 "프론트 별도 레포" 결정을 통합 레포로 변경(계약 문서·DB 스키마 공유) |
| 프론트엔드 | **Next.js + TypeScript** (SSG/ISR — SEO 핵심). `apps/web` |
| 백엔드(서빙) | **Spring Boot (Java) + Gradle(Kotlin DSL)** — REST API. `apps/api` |
| 수집 | **Python + poetry** (상시 서버 아님, 일 1회 실행). `apps/ingest` |
| 데이터베이스 | **PostgreSQL** (JSONB, pg_trgm 필수. 장기 pgvector 옵션) |
| 스키마 관리 | **Flyway = 단일 진실.** Spring `ddl-auto=validate` 고정. Python·Java 공유물은 DB 스키마뿐 |
| 배포 환경 | **하이브리드** (2026-07 배포 결정) — web=Vercel(Next.js SSG/ISR), api+DB=**AWS EC2 단일 인스턴스**(Postgres 컨테이너 · Caddy 자동 HTTPS). Python 배치는 EC2 cron. **RDS 대신 EC2 Postgres 컨테이너**(비용 최소화, MVP) — 정기 `pg_dump` 백업(로컬+S3)으로 DR 보완, 트래픽·데이터 확장 시 RDS·AWS 통합 이전 검토. 도메인 changmun.com(Cloudflare) |
| 사용할 라이브러리 | pg_trgm(검색·dedup 유사도), (프론트) Tailwind 권장 |
| 금지 | MVP에서 크롤링 라이브러리(Selenium 등) 도입 금지 · ORM 자동 스키마 생성 금지(`ddl-auto=update` 금지) · `status` 컬럼 저장 금지(조회 시 계산) · raw 가공 저장 금지(원본 보존) · 개인정보 수집은 로그인 `app_user`의 최소 범위(이메일·provider)만, 그 외 금지 |
| 기존 코드베이스 | 신규 프로젝트(통합 조건 없음) |

## 7. 데이터 모델 & API 개요

### 7.1 핵심 엔티티 (상세: `data-model.md` — LOCKED)
- **opportunity**: 공고 원장. `(source, external_id)` UNIQUE. 페르소나 컬럼 `target_startup_stage[]`·`target_audience_type[]`, dedup 컬럼 `dedup_group_id`·`is_canonical`, 원본 `raw JSONB`
- **glossary**: 용어 사전 (term, description)
- **event_log**: 행동 로그 (append-only)
- `app_user` — 로그인 In-Scope로 당김(data-model §8, 구현). (Phase 3) user_stage_history

**관계**: opportunity 1:N event_log(약결합, FK 강제 안 함) / glossary는 독립(텍스트 매칭)

### 7.2 주요 API (상세: `api-spec.md`)

| 메서드 | 경로 | 설명 | 인증 |
|---|---|---|---|
| GET | /api/v1/opportunities | 리스트 (persona, region, category, status, q, ids, sort, page, size) | N |
| GET | /api/v1/opportunities/{id} | 상세 | N |
| GET | /api/v1/glossary | 용어 사전 전체 | N |
| POST | /api/v1/events | 행동 로그 적재 | N(익명 ID) |

status·D-day·배지 플래그는 **서버가 계산해 응답에 포함**(프론트 재계산 금지).

```
카드/상세에서 찜 → (다음 방문) 찜 목록 → 상세 재진입
```

## 9. 에러 처리 정책

| 상황 | 처리 방식 |
|---|---|
| 사용자 입력 오류 | 인라인 메시지(검색 최소 글자 등) |
| 서버/네트워크 오류 | 토스트 + 재시도 버튼. 로깅(FR-007)은 예외 — 조용히 무시 |
| 로딩 상태 | 스켈레톤 UI(카드 리스트), 상세는 SSG라 즉시 |
| 빈 상태 | 화면별 정의(FR-003/005/006) — 안내 문구 + 다음 행동 유도 |
| 404 / 권한 없음 | 전용 404 페이지(마감 공고는 404 아님 — FR-004) |
| 수집 파이프라인 오류 | 소스 단위 격리(FR-001), 수집 리포트 로그로 익일 확인 |
